**Findings**

1. **FHIRPath KDK date rules are still incomplete.** [kdk.invariants.json](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules/kdk.invariants.json:45) and [:52](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules/kdk.invariants.json:52) omit schema date fields `case.priorProcedures[].therapyResponseDate` and `case.priorRds[].diagnosticDate`. Primitive rules find these via schema walking in [rules.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules.py:89). Fix: generate FHIRPath date collections from the schema walker, or add these paths and regression tests for KDK-6/KDK-7.

2. **KDK-7 allows equal dates although QS says “vor dem Datum”.** Primitive backend only fails `t > anchor` in [rules.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules.py:234); FHIRPath uses `<=` in [kdk.invariants.json](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules/kdk.invariants.json:52). Fix: compare non-anchor dates with strict `<`; primitive should fail `t >= anchor` after excluding anchors, FHIRPath must remove anchor paths from the compared collection before switching to `<`.

3. **Multi-scope MV consent can pick the wrong consent date.** KDK-9b uses the first `mvConsent.scope[].date` in [rules.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules.py:187) and FHIRPath uses `.date.first()` in [kdk.invariants.json](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules/kdk.invariants.json:73). KDK-9a compares against all scope dates in [kdk.rules.json](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules/kdk.rules.json:49). A later unrelated `reIdentification` or `deny` scope can false-fail, and an earlier unrelated scope can false-pass. Fix: select `scope.where(type == "permit" and domain == "mvSequencing").date`.

4. **Follow-up KDK-7 uses the first follow-up date globally.** [rules.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules.py:217) picks the first OD/RD follow-up anchor; FHIRPath does the same with `.first()` in [kdk.invariants.json](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules/kdk.invariants.json:52). Multiple follow-ups can false-fail later follow-up data. Fix: compare each `followUpOds[]` / `followUpRds[]` object against its own `followUpDate`.

5. **TNM primitive and FHIRPath backends disagree.** Primitive TNM accepts category tokens in `display`, `text`, or `code`, anywhere in the string ([rules.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules.py:239)); FHIRPath only checks `display` anchored at string start ([kdk.invariants.json](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/rules/kdk.invariants.json:38)). Fix: mirror the primitive regex and fields in the invariant, or make the primitive intentionally match the invariant.

6. **JSON pointer handling is not RFC6901-safe.** Source map paths are built with raw keys in [validator.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:147), unknown findings emit raw keys in [:273](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:273), schema paths join raw segments in [:335](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:335), and `_to_pointer` returns raw `/...` paths unchanged in [:186](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:186). Keys containing `/` or `~` collide or mis-locate. Fix: centralize `_ptr_escape(segment)` and `_ptr_join(ptr, segment)` and use it in source map, schema findings, unknown walker, and `rules.resolve()`.

7. **Escaped non-BMP object keys mis-locate.** `_source_map.string()` decodes each `\uXXXX` independently in [validator.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:128), so `\uD834\uDD1E` becomes surrogate code units, while `json.loads` produces the actual scalar character. Fix: use `json.decoder.scanstring` for string token decoding.

8. **Unknown-field line/col points to the value, not the key.** `_source_map` records `pos[ptr]` at value start in [validator.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:137). For `"bogus":\n 1`, the unknown field reports line 2, not the field name. Fix: keep a second `key_pos` map and use it for unknown-field findings.

9. **Malformed JSON loses available line/col.** `validate_file()` catches `json.JSONDecodeError` in [validator.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:363) but drops `lineno`/`colno`. Fix: when `isinstance(e, json.JSONDecodeError)`, set `Finding.line = e.lineno`, `col = e.colno`.

10. **No-schema failures have no finding.** Unknown/legacy branches return a failing `Result` with empty findings in [validator.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:329). CLI exits nonzero, but per-file output has no actionable row. Fix: append a schema finding at `(root)` explaining branch classification failure.

11. **`--fhirpath` missing dependency is an unhandled CLI crash.** `invariants._evaluator()` raises `RuntimeError` in [invariants.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/invariants.py:29), but CLI does not catch validation-time runtime errors at [cli.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/cli.py:79). Fix: preflight import or catch `RuntimeError`, print the message, return exit `2`.

12. **Rule skip semantics can produce a misleading PASS.** `Result.ok()` ignores info findings in [validator.py](/Users/kohlbach/Claude/MII/genomde-dk-validator/src/genomde_dk_validator/validator.py:308), so `--kdk-rules` without required config can exit `0` while KDK-2/KDK-11 were skipped. Fix: either make required-config skips fail unless `--allow-rule-skips` is set, or expose `complete: false`/skip counts prominently in JSON and text.
